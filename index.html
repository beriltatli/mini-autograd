The question this answers

What does a framework actually do between loss.backward() and the weight update?

Four things, and Phase 1 implements all four. It records every operation as a node in a directed acyclic graph while the forward pass runs. It orders those nodes so no node is differentiated before its consumers are done. It accumulates — a tensor used twice receives two gradients and they must be summed, not overwritten. And it releases the graph, because a training loop that keeps every intermediate activation alive for 5000 steps is not a training loop, it is a memory leak with a progress bar.

Accumulation · the diamond graph

Two paths, one gradient

This is the whole reason accumulate_grad uses += and not =. x has two consumers, so two gradients arrive at it: 2x down the mul path and 1 down the direct path. An engine that assigns instead of accumulating returns whichever arrived last — 2x or 1, never 2x + 1 — and the bug is invisible on any graph where each tensor is used once, which is most toy examples. test_diamond_graph exists to make it visible.

The hard part · reverse broadcasting

Undoing what NumPy did for free

Broadcasting in the forward pass is replication, and the adjoint of replication is summation: if one value was copied into N output slots, N gradients come back and they all belong to that one slot. NumPy replicates in exactly two steps, so unbroadcast undoes exactly two. First it left-pads the rank with 1s — a (4,) operand used against (2,3,4) is treated as (1,1,4) — and those padded axes are summed away, since the original operand has no such axis. Then it stretches every remaining extent-1 axis, which is summed with keepdims=True, because the original operand still has a length-1 axis sitting right there.

mini_autograd/broadcast.py46 lines
def unbroadcast(grad: np.ndarray, shape: tuple[int, ...]) -> np.ndarray:
    grad = np.asarray(grad)
    if grad.shape == shape:
        return grad

    # (1) undo rank expansion
    extra_dims = grad.ndim - len(shape)
    if extra_dims > 0:
        grad = grad.sum(axis=tuple(range(extra_dims)))
    elif extra_dims < 0:
        raise ValueError(f"cannot unbroadcast {np.shape(grad)} down to {shape}")

    # (2) undo size-1 stretching
    axes = tuple(i for i, dim in enumerate(shape) if dim == 1 and grad.shape[i] != 1)
    if axes:
        grad = grad.sum(axis=axes, keepdims=True)

    # shapes must now agree exactly -- reshape raises if they don't
    return np.asarray(grad).reshape(shape)

That trailing reshape is deliberate paranoia. If the two steps don't land exactly on the target shape it raises, instead of quietly returning a plausible-looking array of the wrong size that would then poison every weight downstream.

Bug #1 — caught by the highlighted row

The last case is the only one that needs both steps, and it is the one that failed. Not an engine bug: unbroadcast sums the replicated axes in two passes while my reference implementation summed them in one, float addition is not associative, and the two disagreed by ~1e-16. The test asserted atol=0, so it only fired on some random draws. The test was wrong; tolerance is now 1e-12.

Ordering

Topological sort, iteratively

A node may only be differentiated once every consumer downstream of it has contributed its share — otherwise a tensor feeding two branches gets pushed upstream while half its gradient is still missing. Post-order DFS over the _prev edges gives inputs-before-consumers; backward() then walks that list reversed, which is consumers-before-inputs, exactly the guarantee needed.

mini_autograd/tensor.py:100Tensor._toposort
def _toposort(self) -> list["Tensor"]:
    topo: list[Tensor] = []
    visited: set[int] = set()
    stack: list[tuple[Tensor, bool]] = [(self, False)]
    while stack:
        node, expanded = stack.pop()
        if expanded:
            topo.append(node)
            continue
        if id(node) in visited:
            continue
        visited.add(id(node))
        stack.append((node, True))          # re-push self *under* its inputs
        for parent in node._prev:
            if id(parent) not in visited:
                stack.append((parent, False))
    return topo

The expanded flag is the iterative equivalent of "code after the recursive call": popping a node the first time schedules it for emission beneath all of its inputs, so it can only be appended once they are all done. It is iterative rather than recursive because Python's recursion limit is around 1000 and a real graph is easily longer — test_toposort_is_iterative_and_survives_a_deep_chain builds a 5000-op chain specifically to fail a recursive implementation.

visited is keyed by id(), so a node with several consumers is emitted exactly once and its _backward() closure runs exactly once. Merging the paths is the job of += inside accumulate_grad, not of visiting a node repeatedly.

Release

The graph has to die

Each _backward closure captures its inputs and its output, so a live graph pins every intermediate activation in memory. After the reverse sweep, _free_graph nulls every visited node's _prev and _backward, turning the whole DAG into garbage the moment the loss goes out of scope. Leaf parameters survive — the model still references them, and they keep their .grad for the optimizer. test_backward_releases_the_graph takes a weakref to an intermediate and asserts it is dead after collection.

Open for review

Two calls worth arguing about

matmul raises on 1-D operands
NumPy silently prepends or appends a 1 to vector operands, which turns the backward pass into a nest of special cases for a convenience a neural net never needs — x @ W is always at least 2-D. It raises a ValueError that suggests the reshape instead. This is a deviation from the brief and it goes in the limitations section.
retain_graph exists after all
The brief asked for teardown and no premature abstraction. One flag went in anyway: without it, a second backward() call fails with a confusing NoneType error rather than an honest one, and the test suite needs a way to inspect a live graph. The default is False — the graph still dies.
